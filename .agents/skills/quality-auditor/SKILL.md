# 品質監査・不備検査プロトコル (Quality Auditor)

本スキルは、AI Companion Studio システムにおいて「モックの残存」「未実装UI」「同一機能の重複ボタン」「UIレイアウトの崩れ」「外部プロセスのゾンビ化リスク」「コーディング規約違反（絵文字混入・日本語Doc漏れ）」といった不備を根絶し、高水準な品質を自動的かつ体系的に保証するための監査手順書です。

---

## 1. 監査の対象と基準

| 監査領域 | 主な検査項目 | 判定基準 (FAIL条件) |
| :--- | :--- | :--- |
| **UI・機能完全性** | モック残存、空イベントハンドラ、未接続ボタン | `onClick={() => {}}` や `モック` 表記のUI、未実装TODOの放置 |
| **UIデザイン・配置** | ボタン重複、画面枠はみ出し、レイアウト崩れ | 同一画面内で同一機能ボタンが乱立、段々畑のような折り返し |
| **モデルレンダリング** | Live2D / VRM 3D の描画完全性 | 画面の白化、モデル極小化、プレースホルダーSVG絵の代用 |
| **プロセス管理** | Windows Job Object 準拠 | `exec.Command` の裸呼び出し（必ず `pkg/process` を経由） |
| **依存性・移植性** | Cgo 非依存 (Pure-Go SQLite) | `import "C"` の混入 |
| **コード規約** | 絵文字完全排除、日本語DOCコメント | 絵文字（Unicodeサロゲートペア/記号）の混入、公開シンボルの日本語Doc欠落 |
| **型安全性** | TypeScript strict モード | 不当な `any` 型の多用（`strict: true` 遵守） |

## 2. 自動監査コマンド (ワンステップ実行)

システム全体の一括監査は、プロジェクトルートまたは `frontend` ディレクトリから以下のコマンドを実行します。

```powershell
# 総合監査スイートの実行 (全項目一括検証)
npm run audit
```

個別の詳細監査を行う場合：

```powershell
# 1. 規約・アーキテクチャ検査 (絵文字/Cgo/JobObject/日本語Doc)
npm run audit:rules

# 2. UI不備・モック残存静的検査 (空ハンドラ/モック表記/重複UI)
npm run audit:ui

# 3. Go バックエンド単体テスト
npm run test:go

# 4. フロントエンド型チェック
npm run test:frontend
```

## 3. Playwright による実機ネイティブ描画検証

Live2D および VRM 3D の実際の WebGL 描画状態をヘッドレスブラウザで視覚的に検証します。

```powershell
# Playwright による実機キャプチャ＆レンダリング検証
cd frontend
node capture_native.mjs
cd ..
```

## 4. 機能追加・コミット前の必須チェックフロー

機能追加やバグ修正を行った際は、**必ずコミット前に以下の順序で監査を実施**しなければなりません。

1. **静的検査**: `npm run audit` を実行し、全項目が `[PASS]`（終了コード0）になることを確認する。
2. **実機描画テスト**: Live2D / VRM の変更を伴う場合は `capture_native.mjs` で実際の描画画像を確認する。
3. **差分レビュー**: `git diff` を確認し、不要なデバッグ出力（`console.log`）や絵文字が混入していないことを最終確認する。
4. **コミット**: コミットメッセージにも絵文字を含めず、明瞭な日本語または英語で記述する。
