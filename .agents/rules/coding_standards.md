# コーディング規約 (Coding Standards)

## 1. コメント言語規約（厳格）
- **DOCコメント・インラインコメントはすべて日本語で記述する。**
- Goの公開シンボル（関数の先頭コメント、構造体、インターフェース）は、Goの標準フォーマット（`// SymbolName は...`）に従い、日本語で意味と用途を明記する。
- TypeScriptのJSDoc（`/** ... */`）も同様に日本語で引数・戻り値を説明する。

## 2. Go 実装規約
- **エラーハンドリング**:
  - `error` を握り潰さない（`_ = err` は原則禁止）。
  - エラーをラップする際は `fmt.Errorf("操作名に失敗しました: %w", err)` で文脈を付与する。
- **並行処理**:
  - goroutine を起動する際は、必ず終了条件（コンテキストの `ctx.Done()` またはチャンネルクローズ）を設ける。
  - プロセス間通信やパイプライン処理はバッファ付きチャンネルを活用し、デッドロックを防止する。
- **リソース解放**:
  - ファイルハンドル、DBコネクション、HTTPレスポンスボディ、OSハンドルは必ず `defer` でクローズする。

## 3. TypeScript / React 実装規約
- **型安全性**:
  - `any` 型の使用禁止。未知のデータには `unknown` を使い、型ガードを実装する。
  - Wails IPCイベントのペイロードはすべて明確なインターフェース型を定義する。
- **React フックとレンダリング最適化**:
  - WebGLキャンバスやAudioContextなどのインスタンスは `useRef` で保持し、不要な再生成・再レンダリングを防ぐ。
  - `useEffect` のクリーンアップ関数で、イベントリスナーやアニメーションループ（`cancelAnimationFrame`）を確実に解放する。
